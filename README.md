# Chronograph: Real-Time F1 Telemetry Analytics

**Chronograph** - это учебный проект, высокопроизводительная система сбора, парсинга и визуализации гоночной телеметрии в реальном времени, разработанная для анализа телеметрических данных из симуляторов Формулы-1 (поддержка спецификации F1 UDP Protocol).

**Цель проекта:** Предоставить пилоту инструмент глубокого телеметрического анализа (входные интерфейсы, траектории, работа с педалями, фазы торможения) для поиска скрытого тайминга и оптимизации гоночного темпа.

---

## 1. Теоретическая база и математика

Для точного анализа поведения болида на трассе система оперирует не только сырыми показателями, но и расчетными физическими величинами.

### 1.1. Анализ эффективности торможения (Braking Efficiency)
Эффективность замедления болида зависит от силы нажатия на педаль тормоза, текущей скорости и термического состояния тормозных дисков. Сила замедления (отрицательное ускорение $a_{brake}$) в определенный момент времени $t$ рассчитывается по формуле:

$$a_{brake}(t) = \frac{\Delta v}{\Delta t} \cdot f(B_{temp}, B_{press})$$

Где:
*   $\Delta v$ — изменение скорости ($km/h$).
*   $\Delta t$ — дискретный шаг времени между UDP-пакетами.
*   $B_{press}$ — линейное давление на педаль (`brake` в диапазоне $[0, 1]$).
*   $B_{temp}$ — температура тормозных дисков (`brakeTemp`).

Система сопоставляет график падения скорости с эффективным температурным окном тормозов для выявления зон преждевременного износа или недотормаживания.

### 1.2. Сглаживание сигналов управления (Signal Smoothing)
Физические датчики рулевого управления (`steer`) и педалей (`throttle`, `brake`) передают данные на высокой частоте (до 60 Гц). Для исключения высокочастотного шума и построения плавных графиков в аналитическом модуле применяется фильтр экспоненциального скользящего среднего (EMA):

$$S_t = \alpha \cdot Y_t + (1 - \alpha) \cdot S_{t-1}$$

Где:
*   $S_t$ — сглаженное значение телеметрии в текущий момент.
*   $Y_t$ — сырое значение из UDP-пакета (`steer` / `throttle`).
*   $\alpha$ — коэффициент сглаживания ($\alpha \in (0, 1]$), настраиваемый в зависимости от частоты обновления.

## 3. Спецификация сетевого протокола
Так как игра отправляет данные в бинарном виде для экономии трафика, критически важно контролировать смещение байт. Проект реализует ручной парсинг структуры данных без использования на сторонние библиотеки. 

### Структура пакета Car Telemetry
Пакет содержит массивы данных для всех 22 болидов на решетке. Система динамически вычисляет смещение игрока через PLAYER_CAR_INDEX_OFFSET (27-й байт):
$$\text{MyStartOffset} = \text{HEADER_SIZE} (29) + (\text{PlayerIndex} \cdot \text{CAR_TELEMETRY_SIZE} (60))$$
Данная структура нужна для корректного получения данных именно той машины, которая принимает UDP пакет.
